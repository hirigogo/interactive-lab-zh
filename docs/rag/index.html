交互式讲解

从零实现 RAG

问聊天机器人昨天选举谁获胜，它会自信地编造一个答案。解决之道？在它作答之前把正确的文档交给它。这就是 RAG—检索增强生成—而你可以用两个早已熟悉的思想把它搭建出来。

拖动数据点、切换领域，观察词元的逐步生成。流水线的每个步骤都是可交互的。

约 12 分钟 深度学习 检索 语言模型
第一部分

问题所在：冻结的知识

语言模型的知识在训练期间被固化在权重之中。训练一旦结束，这些权重便被冻结。由此产生三个在实践中反复出现的问题：

1
知识过时。 询问训练截止日期之后发生的事，模型一无所知。它要么拒绝回答，要么更糟—自信地瞎猜。
2
缺失领域事实。 你公司的内部文档、一篇小众研究论文、某座新城市的 公交时刻表—这些都不在训练数据之中。
3
幻觉。 当模型不知道某事时，它往往不去说「我不知道」，而是编造一个听起来合理 却错误的答案。
核心思想。 与其在知识每次变化时都重新训练模型，不如让它参加一场 开卷考试。在查询时取回相关文档， 并将它们粘贴进提示词。模型阅读这些文本并据此作答—而非凭记忆作答。这就是 RAG。
第二部分

两个基本构件

RAG 恰好组合了两个思想。如果你上过机器学习入门课程，两者你都已经知道。在把它们连接起来之前，我们先确认对它们的理解一致。

构件 1

下一词元预测（语言模型）

语言模型接收一个词元序列，并预测接下来是什么。GPT、LLaMA、Claude—它们都以此方式工作，一次预测一个词元。模型「所知道」的一切都存在于其权重之中。这被称为 参数化记忆—训练结束后便固定下来。

构件 2

k 近邻（kNN）

将项目表示为向量（空间中的点）。给定一个查询向量， 找出最近的 k 个点。查询时无需学习—纯粹的 几何。若两份文档主题相近，它们的向量 便会彼此靠近。

暂停思考。 语言模型能生成流畅的文本，却可能凭空捏造事实。kNN 能找到 相关文档，却写不出句子。RAG 将二者串联： kNN 检索事实，语言模型将其转化为答案。 二者单独都无法完成这项任务。

第四部分：第 1 步

嵌入文档

以下是我们迷你语料库中的五份文档。在真实系统中，会有成千上万乃至 数百万份—但五份已足以看清其机制。

编码器模型（如 Sentence-BERT）读取每份 文档并输出一个 向量—一串捕捉文档语义的 数值。主题相近的文档会产生相似的向量。在真实系统中，这些向量为 768 维或 更高，但为了便于可视化，我们采用 二维嵌入。

文档的二维嵌入

下方每个蓝点是一份文档，按其二维嵌入坐标 绘制。注意主题相关的文档如何聚拢在一起。 

docs  = split(corpus)       # 将文本切分为段落
emb   = encoder(docs)       # 嵌入每个块 → 向量
index = FAISS(emb)          # 构建可检索的索引
什么样的嵌入才算好？ 「德里的冬季 PM2.5」应当落在「加尔各答的冬季雾霾」附近，而远离 「玫瑰奶球是油炸的」。编码器在其自身于大规模文本语料上的训练过程中 学会了这些距离。

为何取 top-k 而非全部？ 语言模型的上下文窗口有限（通常为 4K–128K 词元）。我们 无法粘贴每一份文档，因此只选取最相关的 k 份。 选择 k 是一种权衡：太小会遗漏上下文；太大 则无关文档会淹没信号。
第七部分：第 4 步

构建提示词

这里是检索与生成交汇之处。我们取检索到的 文档与用户的问题，将它们拼接成一个 文本块—即语言模型将要阅读的提示词：

上下文（检索到的文档）
问题（用户查询） 
q_emb  = encoder(query)            # 第 2 步：嵌入查询
docs   = index.search(q_emb, k=2)  # 第 3 步：检索 top-2
prompt = concat(docs, query)        # 第 4 步：组装提示词
output = LLM(prompt)                # 第 5 步：生成答案

提示词组装完成后，RAG 的检索任务便告结束。 此后便是标准的语言建模—语言模型阅读 提示词，逐词元生成答案。

以绿色高亮的词元直接 来自检索到的上下文。模型并非在做字面意义上的「复制」—只是 在下一词元预测下，上下文使这些特定词语 变得极可能出现。

语言模型如何使用上下文？

通过 自注意力机制。在生成每个输出 词元时，模型会关注提示词中的所有词元—包括 检索到的文档。它自然地聚焦于最相关的上下文 词元：

单元格颜色越深 = 注意力权重越高。当模型生成 「Delhi」时，它会高度关注上下文中的「Delhi」。当它生成 「PM2.5」时，它会关注「PM2.5」。注意力机制正是 RAG 在神经网络层面得以奏效的原因。

三项具体的收益

  • 减少幻觉。 语言模型有真实的文本可供 参照，从而远不易凭空捏造事实。
  • 始终最新。 需要更新的知识？更新 文档库即可。无需重新训练—只需重建索引。
  • 比微调更经济。 模型权重保持 冻结。只有索引发生变化。更新知识无需 GPU。

RAG 与 kNN-LM：一处微妙的区别

方法检索单元使用方式
kNN-LM（kNN 语言模型）单个词元在每一步插值进输出 logit
RAG（检索增强生成）整份文档前置到输入提示词之前
一句话总结。 RAG = 对知识做 kNN + 对文本做语言模型。 参数化记忆（模型所学）+ 非参数化记忆 （你刚刚检索到的内容）。
第十一部分

RAG 何时失效

RAG 强大，但并非魔法。理解其失效模式 将为你省下大量调试时间：

1. 检索器取回错误的文档

若嵌入模型对你的领域理解不足，它 可能检索到表面上相似但语义上错误的文档。 垃圾上下文输入 → 垃圾答案输出。 嵌入模型的质量就是 RAG 性能的上限。

2. 上下文稀释（k 过大）

向提示词塞入过多文档会使注意力被摊薄。 那一份相关文档被掩埋在九份无关文档之中。 更小、更精确的 k 常常胜过更大的 k。

3. 冗余文档浪费上下文

五份内容雷同的文档会占用宝贵的上下文 窗口，却不增添任何新信息。多样性感知的检索 （如 MMR—最大边际相关性）对此有所帮助。

4. 无法进行多跳推理

若答案需要综合文档 A 与文档 B 中的 事实，语言模型往往力不能及。它倾向于从单份 文档中抄袭，而非跨多份文档进行综合。这是一个 活跃的研究方向。

引用并不等于证据。 即便模型写下「[来源 1]」，它也可能引用了错误的文档， 或曲解了该文档的内容。语言模型输出中的引用是一种习得的 输出模式，而非一种有据可依的机制。务必核实。
第十二部分

我们构建了什么

  • RAG = 检索 + 生成。 在嵌入空间中找出最近的 文档，将其粘贴进提示词，然后让 语言模型依据文本作答。
  • 五个步骤。 嵌入 → 建索引 → 检索 → 构建提示词 → 生成。
  • 改善输入，而非改善模型。 RAG 并不 改变模型权重—它改变模型所看到的内容。 底层的数学依旧是下一词元预测。
  • 注意力机制是其机理。 语言模型通过 自注意力机制关注上下文词元，自然地将相关事实 引入其输出。
  • 认清其局限。 劣质嵌入、稀释的上下文、 冗余文档以及多跳推理，正是 RAG 失效之处。 没有任何工具是万灵药。
