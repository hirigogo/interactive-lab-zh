一句话洞察本质

你希望对预训练权重所作的改变通常是低秩的（Hu 等，2021）。你并不需要 700 亿参数的更新预算 —— 你需要的只是一处微小的修正。因此，与其微调 $W \in \mathbb{R}^{d \times d}$，不如将更新参数化为

其中 $B \in \mathbb{R}^{d \times r}$、$A \in \mathbb{R}^{r \times d}$，且 $r \ll d$。基座 $W_0$ 保持冻结；只有 $A$ 与 $B$ 获得梯度。标量 $\alpha/r$ 使有效步长在不同秩之间保持稳定。在初始化时 $B = 0$，因此 LoRA（低秩适配） 项恒为零，模型恰为预训练模型 —— 这是一个有保证的起点。

为何「低秩更新」是恰当的先验

Hu 等的论文测量了在下游任务上微调预训练 transformer 的内在维度，发现它极小 —— 当 $d = 4096$ 时往往低于 $r = 8$。对此有两种理解方式：

  • 实证角度。 与预训练（万亿词元）相比，微调数据集很小（数千个样本）。微调数据中的信号不足以让权重沿数千个独立方向移动；只有少数几个方向占主导。
  • 几何角度。 预训练特征已经张成了大部分有用的子空间。微调只是将该子空间轻微旋转，而这恰恰就是一个低秩扰动。

对于 7B 模型，在 $r = 8$ 时你有约 400 万个可训练参数。你可以在单张 24 GB 消费级 GPU 上完成微调，将适配器保存为约 16 MB 的文件，并与基座权重一同分发。基座从不改变 —— 你可以在其上叠加许多适配器。

超参数的选择与设定方法

1. 秩 $r$

对大多数 LLM 任务而言 $r \in \{4, 8, 16\}$ 已足够。除非你的任务对模型作出显著适配 —— 例如注入一种全新的模态 —— 否则更大的 $r$ 并无助益。若怀疑需要更高的秩，可按对数尺度扫描 $r$。

2. 缩放系数 $\alpha$ 与 $\alpha/r$ 约定

$\alpha$ 是推理时施加于 $BA$ 的标量。约定「$\alpha/r$」可在扫描 $r$ 时使 LoRA（低秩适配） 项的有效学习率大致保持恒定 —— 便于超参数搜索。常见取法：$\alpha = 2r$，或不论 $r$ 如何均取 $\alpha = 16$。

3. 注入哪些模块

原始论文仅推荐 $W_q$ 与 $W_v$。较新的实证研究（Dettmers、Pagnoni 等，2023）为获得最佳质量，往往注入全部 $\{W_q, W_k, W_v, W_o\}$ 以及 MLP 的上、下投影。成本与注入模块数量成正比。

4. Dropout（丢弃法）

在 LoRA（低秩适配） 路径内部使用较小的 dropout（0.05–0.10），可在小规模微调集上稳定训练，且不影响基座。对于极小的适配器可略去。

数学细节

前向传播变为

在初始化时：$A \sim \mathcal{N}(0, \sigma^2)$（Kaiming 式），$B = 0$。于是 $BA = 0$，模型输出恰为预训练模型。关键在于，这意味着在训练做出任何有益之事之前，LoRA（低秩适配） 从不损害基座。

训练之后，你有两种选择：

  • 将 LoRA（低秩适配） 模块保持独立。 每层推理前向传播的开销为 $O(d^2 + 2rd)$。这使你能在服务时切换或组合适配器。当你希望在一个基座上托管众多任务专用适配器时使用。
  • 合并进基座。 令 $W \leftarrow W_0 + \frac{\alpha}{r} BA$。推理与基座完全相同 —— 零开销。当该适配器即为最终版本时使用。

QLoRA（低秩适配）（量化 LoRA（低秩适配）） —— 在单张 48 GB GPU 上微调 70B

QLoRA（低秩适配）（量化 LoRA（低秩适配））（Dettmers 等，2023）即「在 4 位基座上做 LoRA（低秩适配）」。包含三个部分：

  • NF4 量化。 4 位正态浮点 —— 其设计使量化分桶与预训练权重的分布相匹配。体积约为 fp16 的 1/4。
  • 二次量化。 对量化常数本身再作量化；可再节省若干比特。
  • 分页优化器。 使用统一内存，使优化器状态在梯度累积的高峰期溢出到 CPU。

基座以 4 位冻结存放，在做矩阵乘法时即时反量化；LoRA（低秩适配） 路径则保持 fp16/bf16。最终结果：以一小部分显存获得与 fp16 LoRA（低秩适配） 相同的精度。

PyTorch + peft 代码示例

from peft import LoraConfig, get_peft_model

lora_cfg = LoraConfig(
    r=8,                           # rank
    lora_alpha=16,                 # scale
    target_modules=["q_proj", "v_proj"],  # where to inject
    lora_dropout=0.05,
    bias="none",
)
model = get_peft_model(base_model, lora_cfg)
model.print_trainable_parameters()
# > trainable params: 4.2M   all params: 7B   trainable%: 0.06%

实践中的坑

  • 灾难性遗忘。 由于基座保持冻结，LoRA（低秩适配） 的遗忘少于全量微调，但在域外生成上仍会漂移。应使用较小的学习率（典型为 1e-4）、早停，以及一个留出的域外评估集。
  • 混合适配器。 适配器专家混合（LoRA（低秩适配）Hub、Composing-LoRA（低秩适配）s）使你能在推理时线性组合各任务适配器。对密切相关的任务有效；对相互正交的任务则迅速退化。
  • 不要用 LoRA（低秩适配） 做从零预训练。 低秩先验仅当存在一个强大的预训练初始化可供扰动时才成立。预训练请使用全秩。
  • 合并多个适配器。 $W_0 + \sum_i \frac{\alpha_i}{r_i} B_i A_i$ —— 但它们可能相互干扰。在堆叠许多适配器时，使用 TIES 合并或 DARE 可获得更干净的结果。
  • 量化推理与 fp16 推理。 若你使用 QLoRA（低秩适配）（量化 LoRA（低秩适配）） 训练，仍可以 fp16 部署合并后的模型 —— 只需在合并前将基座反量化一次。
最终要点。

LoRA（低秩适配） 是一种罕见的技术：「偷懒」的做法竟然能与严谨的做法相匹敌。对于参数规模 > 10 亿的预训练模型上 99% 的微调任务，都从 LoRA（低秩适配） $r=8$、$\alpha = 16$、注入 $\{W_q, W_v\}$ 开始。若无法承担 fp16 基座的成本，则转向 QLoRA（低秩适配）（量化 LoRA（低秩适配））。只有在测到真实差距之后，才考虑 DoRA / AdaLoRA（低秩适配）（自适应秩分配）。
