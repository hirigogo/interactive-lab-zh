第 4 步

非极大值抑制（NMS）

检测器会对同一目标多次响应。NMS 是经典的去重规则：

  1. 按置信度从高到低对检测排序。
  2. 保留排名最高的检测。
  3. 丢弃所有与已保留检测的 IoU 超过 NMS 阈值的其他检测。
  4. 对剩余的检测重复上述过程。

COCO-SSD 内部已经应用了自己的 NMS。为了观察 NMS 的实际运作，我们以 maxNumBoxes: 40 和内部 IoU 阈值 1.0 加载检测器——这意味着在模型层面 没有任何 检测被抑制。随后你将在下方自行应用 NMS。

第 5 步

检测器家族

本页运行的 SSD 只是更大设计空间中的一个点。三大主流家族为：

家族如何提出框代表模型注意事项
基于锚框（本页） 在多种尺度 / 宽高比上布置的先验框稠密网格；每个框预测类别 + 偏移量。 SSD、Faster R-CNN、RetinaNet、YOLOv3/v4/v5 需要 NMS。锚框超参数较为敏感。
无锚框 / 基于点 逐像素（或逐单元）：预测「我是否是中心？」+ 框的范围。 FCOS、CenterNet、YOLOX、YOLOv8 匹配损失（assignment loss）更为棘手；通常仍使用 NMS。
基于集合（DETR 风格） 固定的可学习查询集合；与 GT 进行匈牙利匹配。 DETR、Deformable DETR、DINO 无需 NMS。训练缓慢；最初在小型目标上表现较弱。
第 6 步

第 7 步

仍然会难住人们的四件事

误区

「99% 置信度意味着模型是对的。」
现代检测器的校准很差。上传一张包含临界情形的照片，你会看到 SSD 在看似合理的错误框上飙升至 0.9。请使用 PR 曲线，而非原始数值。

误区

「NMS 只是清理工作。」
在拥挤场景中，经典 NMS 会 删除真实的重复目标。试一张两只猫挨着坐的照片，观察其中一个框被抹掉。那是 Soft-NMS / DETR 的领域。

误区

「mAP 概括了一切。」
也许你想要任意精确率下的 100% 召回率（医学扫描），或者任意召回率下的 100% 精确率（自动驾驶）。在选定模型之前，请始终绘制完整的 PR 曲线。

误区

「框越大越安全。」
严格包含真实框的预测，其 IoU = 真实/预测。巨大的「安全」框会拖垮 IoU。紧致者胜。

最终总结。 你刚刚在真实图像上运行了一个真实的 COCO 检测器，用手绘的真实标注度量了它的输出，并观察到精确率、召回率、NMS 与 AP 都如数学所预测的那样表现。现代检测研究的其余部分，就是用一个更好的骨干网络（ViT、ConvNeXt）、更好的匹配方式（基于集合、无锚框）以及更好的损失函数来替代 SSD——但每一个部分最终都落到同一张记分板上。
第 8 步

架构谱系图

  • 两阶段：R-CNN → Fast R-CNN → Faster R-CNN。 先提出候选区域，再进行分类与精修。准确但缓慢。
  • 带锚框的单阶段：SSD、YOLO v1–v5、RetinaNet。 锚框的稠密网格；对每个锚框预测（类别, 偏移量）。速度快，在消费级 GPU 上可实时运行。
  • 无锚框：FCOS、CenterNet。 在每个空间位置直接预测（类别, 框），无需调校锚框。更简单，精度具竞争力。
  • 基于集合：DETR（2020）、Deformable DETR、DINO、RT-DETR。 带目标查询的 Transformer 解码器；无需 NMS —— 训练时的二分匹配确保每个目标只有唯一预测。2024 年以后精度优先检测的默认方案。
  • 开放词汇：Grounding DINO、OWL-ViT、OmDet。 检测由自由文本描述的任意类别。将视觉骨干网络与语言编码器相结合。
第 9 步

匹配问题 —— 锚框、FCOS、匈牙利算法

训练期间，每个预测框都必须匹配到一个真实标注框（或被标记为「背景」）。这种 匹配（assignment） 是各检测器家族之间最大的差异。

  • 基于锚框。 若 $\mathrm{IoU}(a, g) > \tau$（典型值 $\tau = 0.5$），则位于锚框 $a$ 处的预测框与 GT $g$ 匹配。简单，但锚框尺度/比例的选择是一个超参数。
  • 基于中心（FCOS）。 若某空间位置位于 $g$ 内部，且处在以其中心为基准的、随尺度变化的带状区域内，则该位置与 GT $g$ 匹配。无需锚框。
  • 匈牙利 / 二分匹配（DETR）。 求解一个分配问题，使每个 GT 恰好匹配 一个 预测，并最小化一个（代价 + IoU + 类别）损失。没有重复预测就意味着无需 NMS 后处理。

基于集合的 DETR 式匹配是一项突破，它最终使 Transformer 检测器能够与单阶段 CNN 相抗衡。一旦移除了人工设计的匹配规则，扩大骨干网络的规模就能带来干净的性能提升。
