交互式讲解

把 KV 缓存讲明白

LLM 每生成一个词元，都要重新读取此前所有词元的 key 与 value。 将它们缓存起来是必需的——而缓存很快就会远超权重本身。 拖动下方的模型、上下文与批量滑块，观察 KV 缓存超过参数的那一瞬间。 这正是“LLM 推理受内存限制，而非受算力限制”的原因。

约 11 分钟 推理 · LLM 系统
前言

缓存为何必须存在

为预测词元 $t{+}1$，自注意力会把当前的 query 与此前每一个词元的 key 进行比较，并按权重混合它们的 value：

$$\mathrm{attn}(q_t) = \sum_{i \le t} \mathrm{softmax}\!\big(q_t \cdot k_i / \sqrt{d_h}\big)\, v_i .$$

过去词元的 key $k_i$ 与 value $v_i$ 永不改变。若在每一步都重新计算它们， 会使生成的时间代价无谓地变为 $\mathcal{O}(n^2)$。因此我们把它们缓存起来： 一个词元处理完毕后，它的 $k$ 与 $v$（在每一层、每个注意力头中）就被存储并永久复用。 这种权衡——用内存换取算力——正是自回归解码得以快速的原因， 也正是它受内存限制的原因。每个新词元都要把整个缓存从 HBM 中读回； 相对于所搬运的字节数，其中的算术运算微不足道。

第 1 步

支配一切的唯一公式

对单个词元、在单层中而言，一个注意力头存储一个 key 向量与一个 value 向量， 其维度均为 $d_h$。在整个模型上相乘展开，就得到每个词元的缓存大小：

$$\underbrace{\text{bytes}_{\text{token}}}_{\text{per token}} = \underbrace{2}_{K \text{ and } V}\cdot\; L \;\cdot\; n_{kv} \;\cdot\; d_h \;\cdot\; p$$
  • $L$ — Transformer 层数（缓存按层存储一次）。
  • $n_{kv}$ — key/value 注意力头数。在多头注意力下它等于 query 头数； 分组查询注意力与多查询注意力会把它缩小。
  • $d_h$ — 每个注意力头的维度。
  • $p$ — 每个数值占用的字节数（FP16 = 2，INT8 = 1）。
  • 系数 $2$ 是因为我们既存储 key又存储 value。

再乘以上下文长度与批量大小（并发序列数），就得到总占用： $\;\text{bytes}_{\text{total}} = \text{bytes}_{\text{token}} \cdot \text{context} \cdot \text{batch}.$ 这里没有任何一项依赖于 MLP 的规模或词表大小—— 缓存完全是注意力形状的纯函数。是时候让它动起来了。

实验台

内存悬崖计算器

用滑块设定一个模型，或用预设加载一个真实模型。图表以上下文长度为横轴绘制两条曲线： 水平的模型权重与上升的KV 缓存。 缓存曲线超过权重之处即为内存悬崖——越过它之后， 你的 GPU 花在记住对话上的内存就超过了模型本身。

第 2 步

Paged注意力类型（分页注意力）：不要再预留你用不到的内存

还有第二重更隐蔽的浪费。朴素的服务器不知道回复会有多长， 于是会为每条序列的事先按最大上下文预留一块连续缓冲区。 多数回复都很短，因此这块缓冲区大部分都空着——即内部碎片。 vLLM 的 Paged注意力类型（分页注意力） 借用了操作系统的分页思路：内存是 一池固定大小的块，序列只在增长时才抓取新的块。 在两种方式之间切换，观察被浪费（斜线填充）的内存如何坍缩。

分配策略

已存储词元 已预留且浪费
已用内存 — 承载真实词元的块
预留总量 — 为之付出代价的块
利用率 — 已用 ÷ 已预留
为何重要。 朴素预留常常浪费 60–80% 的 KV 内存。通过分页，vLLM 把利用率保持在接近 100%，这意味着同一块显卡上能容纳远更多的序列—— 在完全相同的硬件上获得更高吞吐。更小的块在尾部浪费更少， 但会增加记账开销；每块 16–128 个词元通常是最佳折中。
第 3 步

三条逃生出口

$2 \cdot L \cdot n_{kv} \cdot d_h \cdot p$ 中的每一项都是一个杠杆， 而该领域已经把每一个都拉动过：

缩小 n_kv

分组查询注意力

让若干个查询头共享一个 key/value 头。GQA（分组查询注意力）(8) 把 $n_{kv}$ 从 64 降到 8——缓存缩小 $8\times$，而质量损失可忽略不计。 MQA（多查询注意力） 则以单个 KV 头把它推向极致。

缩小 p

INT8 / FP8 KV 缓存

把 key 与 value 用 8 位而非 16 位存储。字节数减半， 通常无需付出代价；偶尔会有轻微精度波动。在实验台中切换它， 悬崖会向右移动两倍远。

停止浪费

Paged注意力类型（分页注意力）

以固定大小的块分配 KV，而非为每条序列分配一整块连续缓冲区。 没有碎片，没有超额预留——这正是 vLLM 高吞吐的核心技巧。

要点。 KV 缓存是长上下文与高并发所隐含的代价。 其规模完全由注意力形状决定 — $2 \cdot L \cdot n_{kv} \cdot d_h \cdot p$ — 且它既随每段对话的长度增长， 也随同时进行的对话数量增长。大规模部署 LLM，粗略地说， 就是把这一个数字压小的艺术。
