交互式讲解

数值计算的实用技巧

浮点运算有其极限 —— $e^{1000}$ 会溢出为无穷， $\log(0)$ 会爆炸为 $-\infty$，而微小的差值会消失为零。 若无若干使数学保持可靠的技巧，现代深度学习将无从谈起。 本页让你亲眼看到朴素计算如何失效，再看技巧如何将其修复。

约 14 分钟 深度学习 · 数值稳定性 · 浮点数
前言

$e^{1000}$ 带来的问题

Float64（NumPy 的默认类型）可表示的数值上限约为 $10^{308}$。Float32（PyTorch 的默认类型）仅约为 $10^{38}$。 这听上去极为巨大 —— 直到你意识到 $e^{100} \approx 10^{43}$ 就已经使 float32 溢出，而 $e^{1000} \approx 10^{434}$ 会使 所有类型都溢出。

这并非假想的顾虑。真实网络中的 logit 轻易就能达到 50 或 100 的量级。交叉熵损失要除以极小的概率。 Sigmoid 会饱和到 0 或 1。凡此种种都会埋下数值计算的隐患。

Float64 的极限： 最大值 ≈ 1.8 × 10308，最小正规格化数 ≈ 2.2 × 10-308
Float32 的极限： 最大值 ≈ 3.4 × 1038，最小正规格化数 ≈ 1.2 × 10-38

好消息是：每一个常见的陷阱都有众所周知的修复方法。读完本页， 你将在同一组 logit 上看到其中最重要的四个陷阱如何失效、 又如何被挽救。

技巧 1

Log-sum-exp：通用的稳定化手段

机器学习中的许多量都归结为计算 $\log\sum_i e^{x_i}$。这听上去 无害。直到某个 $x_i$ 很大 —— 此时 $e^{x_i}$ 溢出，求和结果为 $\infty$，而 $\log\infty = \infty$。

$$\mathrm{LSE}(\mathbf{x}) = \log \sum_{i=1}^n e^{x_i}$$

技巧在于把最大值提取出来：

log Σ exp(xᵢ) = log [exp(m) · Σ exp(xᵢ - m)] 其中 m = max(xᵢ) = m + log Σ exp(xᵢ - m)

此时 exp 内部最大的自变量恰为 $0$，因此 $e^0 = 1$ 总是 可表示的，而其余每一项都落在 $[0, 1]$ 内。在数学上与 朴素形式完全相同，但绝不会溢出。

向量：$\mathbf{x} = [x_1,\ 1.5,\ 0.2,\ -2.0]$。用两种方式计算 $\log\sum e^{x_i}$。

朴素 — 直接公式
稳定 — log-sum-exp 技巧
你会在何处见到它。 在 PyTorch、JAX 与 TensorFlow 中 每一个 softmax、log-softmax 与交叉熵 的实现里。在基于能量的模型的配分函数里。在序列模型的 束搜索里。在两个类别分布之间 KL 散度的 计算里。若你只记住一个数值技巧，那便是它。
技巧 2

Log-softmax：并非 (log ∘ softmax)

交叉熵需要 $\log p_k$。朴素的复合写法为：

$$\log p_k = \log\left(\frac{e^{z_k}}{\sum_j e^{z_j}}\right)$$

以朴素方式计算（先算 softmax，再取对数），它会在两处失效：

  • 指数求和可能溢出（又回到技巧 1）。
  • 若某个 $p_k \approx 0$，则 $\log p_k \to -\infty$，梯度随之爆炸。

干净的写法直接使用 log-sum-exp：

log p_k = z_k - log Σⱼ exp(zⱼ) = z_k - LSE(z) = z_k - max(z) - log Σⱼ exp(zⱼ - max(z))

任何小概率的指数都不再被计算。PyTorch 正是 因为 log(softmax(x)) 的复合写法脆弱， 才将这一运算暴露为 F.log_softmax。

向量：$\mathbf{z} = [z_{\max},\ 0,\ z_{\min}]$。计算 $\log p_{\min}$ — 即 最小 类别的对数概率 — 这是一个危险的对象。

朴素 — log(softmax(z))
稳定 — log_softmax(z)
试试危险区。 将 $z_{\max}$ 推至 200 — 朴素 softmax 溢出（$e^{200} = \infty$）， 于是最大类别得到 $\log(\infty) = \infty$，而最小类别得到 $\log(\text{NaN}/\infty)$。将 $z_{\min}$ 推至 -200 — 朴素算法计算 $e^{-200}$， 它下溢为 0，于是 $\log 0 = -\infty$。稳定版本能同时处理 两者：它只返回 $z_{\min} - z_{\max}$ 再减去一个小修正量。
技巧 3

BCE-with-logits：避开“sigmoid 取对数”陷阱

二元交叉熵为：

$$\mathcal{L} = -y\log\sigma(z) - (1-y)\log(1 - \sigma(z))$$

$\log\sigma(z)$ 与 $\log(1 - \sigma(z))$ 都是定时炸弹。若 $z$ 为强负值，则 $\sigma(z) \to 0$，而 $\log 0 = -\infty$。若 $z$ 为强正值，则 $1 - \sigma(z) \to 0$，问题相同。

修复方法利用恒等式 $\log\sigma(z) = -\log(1 + e^{-z}) = -\mathrm{softplus}(-z)$ 以及 $\log(1 - \sigma(z)) = -z - \log(1 + e^{-z}) = -z - \mathrm{softplus}(-z)$。 代入得：

L = max(z, 0) - z·y + log(1 + exp(-|z|))

此式 绝不会 溢出：唯一的 exp 是 $e^{-|z|}$，它落在 $(0, 1]$ 内。 PyTorch 将其实现为 F.binary_cross_entropy_with_logits。 手工复合 BCE(sigmoid(z)) 是错误的做法。

朴素 — log(sigmoid(z))
稳定 — BCE-with-logits
这一模式。 每当你在代码中看到 “先施加 $\sigma$ 再取 $\log$”， 都应停下来想一想。框架中几乎总有一个融合的单一运算 能稳定地完成它。这与 log_softmax 是同一个教训：当存在稳定的 原子运算时，绝不要复合不稳定的基本构件。
技巧 4

log(1 - exp(-x)) 及其灾难性抵消的近亲

函数 $\log(1 - e^{-x})$ 出现在生存分析、 Beta 分布的对数密度以及某些 KL 散度之中。对于较小的 $x$ （比如 $x = 10^{-5}$），$e^{-x} \approx 1 - x$，故 $1 - e^{-x} \approx x$，但 减法 $1 - e^{-x}$ 会 抵消 掉浮点表示中几乎所有的 有效位。精度由此丢失。

$$\log(1 - e^{-x}) = \begin{cases} \log(-\mathrm{expm1}(-x)) & x \le \log 2 \\[2pt] \log\!1\!\mathrm{p}(-e^{-x}) & x > \log 2 \end{cases}$$

两个专用的库函数 expm1（$e^x - 1$）与 log1p（$\log(1 + x)$），恰好在朴素公式丢失精度的 区域保持精度。它们之所以存在于 C 标准库、NumPy 与 PyTorch 中， 正是出于这一原因。

滑块值为 $\log_{10}(x)$，故实际的 $x$ 从 $10^{-12}$ 变化到 $10^3$
朴素 — log(1 - exp(-x))
稳定 — 使用 expm1 / log1p

将 $x$ 降至 $10^{-7}$。朴素版本要么返回 $-\infty$（当 $1 - e^{-x}$ 舍入为恰好 0 时），要么返回一个缺失 6 位精度的 数值。稳定版本精确到机器 epsilon。

第 6 步

三条经验法则

法则 1

绝不要将 log 与可能极小的量复合。 log(softmax(x))、log(sigmoid(x)) 以及 log(1 - sigmoid(x)) 都在禁止之列。应改用融合的稳定原子运算。

法则 2

绝不要对无界的量计算 exp。 务必先做平移：减去最大值、归一化，或提取出最大项。 数学答案不变，而数值答案保持有限。

法则 3

信任框架提供的 *_with_logits 函数。 它们之所以存在，正是因为朴素复合写法不稳定。cross_entropy(logits, y)、 bce_with_logits(z, y)、log_softmax(z)、logsumexp(z) — 请使用它们。

最后总结。 数值稳定性在正常工作时不可见，一旦失效则后果灾难性。 NaN 损失、梯度爆炸、莫名其妙的训练失败 — 其中很大一部分都可追溯到本应使用融合稳定形式 的朴素复合写法。下次当你的损失变成 nan 时，请先检查你的 log 与 exp。 你通常会在那里找到元凶。
