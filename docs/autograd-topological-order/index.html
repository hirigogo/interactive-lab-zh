反向传播为何需要一种顺序

只有当所有下游路径都已对该节点作出贡献之后，梯度才能流经该节点。拓扑排序恰恰为我们提供了这样一种安全的调度方案。

当前各结构的含义

stack 回答「哪些调用正在等待？」· seen 防止同一个共享 Value 被调度两次 · safe_order 是即将被反转的列表。

反转一次 · 反向传播调度

为何每个节点都已就绪：反转后，输出被置于它能够更新的操作数之前。因此，在某个节点将该节点已完成的梯度发送给自己的父节点之前，所有可能对该节点的 .grad 作出贡献的后续输出都已执行完毕。

进入 开始一次调用并标记为新的 追踪链接 递归至某个操作数 跳过已见过 对共享 Value 立即返回；此图恰好从不需要它 追加 父节点均已完成 回退 子调用已返回 返回 排序已完成 反转 进入反向传播调度 当面板本身获得焦点时的键盘操作：← 上一步 · → 下一步 · 空格 播放/暂停 · Home 重置。
依赖优先顺序： w → x → m → b → a → y → e → L
为反向传播反转后： L → e → y → a → b → m → x → w
每个操作数都出现在使用它的输出之前；反转后，每个输出在向自己的操作数发送梯度贡献之前就已就绪。
