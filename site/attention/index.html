注意力机制的精算

选定一个歧义词，拖动其 Query 向量，观察 Transformer 如何判断该倾听哪些邻词——随着箭头移动，每个点积、 softmax 权重与 value 混合都实时计算。

约 15 分钟 深度学习 · Transformer · 注意力机制
前言

歧义问题

孤立的词几乎没有意义。以 bank 为例。它指的是 河岸，还是 银行？单看这个词无法判断——你必须 考察它的邻词。

自注意力机制正是 Transformer 让每个词 向周围询问 的方式。 句子中的每个词都向其余所有词发问：“我应当 在多大程度上关注你？”答案以一个介于 0 与 1 之间的数值返回。 随后每个词以邻词含义的加权混合来重建自身。

本页将上述过程全部显式展开。读到最后，你将亲手把 原始分数送入 softmax，观察混合 value 向量的形成， 并建立起关于 Transformer 何以在消歧任务上胜过此前 各类架构的直觉。

第 1 步

每个词承担的三种角色

在 Transformer 中，每个词都关联着三个相互独立的 向量，各自扮演不同角色：

  • Query（$Q$）：“我在寻找什么？” 这是希望对自身进行更新的那个词的视角。
  • Key（$K$）：“我能提供什么？” 其余每个词都在此展示自身的特征。
  • Value（$V$）：“若你决定关注我， 以下便是我实际贡献的含义。”

Query 与 Key 决定关注的 程度。Value 决定 所混合的内容。将这两种角色区分开来， 正是注意力机制具备表达力的原因所在。

图书馆类比。 设想你走进一座图书馆，手里拿着一张写有问题的便笺 （即你的 query）。每本书都有书脊标签 （key），书内则有正文（value）。你将 便笺与书脊标签逐一比对，抽出相符的书， 再阅读其正文。这便是注意力机制的一步。
第 2 步

Q、K、V 的实际来源

第 1 步将 Q、K、V 描述为一个词所扮演的三种角色。那么 这些向量在物理上从何而来？它们都是同一个输入嵌入 $x_i \in \mathbb{R}^{d_{\text{model}}}$ 的 线性投影。三个矩阵 $W_Q, W_K, W_V$ 只需学习一次，并在所有位置间共享：

同一输入，三种不同的旋转。query 旋转提取出“我在寻找什么？” 这类特征，key 旋转提取出“我展示什么？”这类特征， 而 value 旋转则提取出“若被关注，我交付什么？”。一个词 之所以扮演三种角色，是因为有三个独立的矩阵经过训练， 以三种不同方式解读它。

第 3 步

点积 = 相容性得分

如何度量一个 Query 与一个 Key 的匹配程度？我们使用 点积。若两个向量方向相同， 得分即为较大的正值。若彼此垂直，则为零。若 方向相反，则为负值。

真实 Transformer 中的缩放点积。 在实际实现中，点积会除以 $\sqrt{d_k}$（其中 $d_k$ 为 key 的维度）。当维度 很大时，原始点积会急剧膨胀，把 softmax 压成 one-hot。 该缩放因子使梯度保持健康。在二维情形下我们将其忽略， 因为影响微乎其微。
第 4 步

Softmax 将得分转化为百分比

原始点积并不是权重——它们可能为负，也可能 极大。我们需要让它们表现得像求和为 1 的概率。 Softmax 恰好能做到这一点：

取指数会放大差异：一个仅略高于其余项的得分 会急剧上升，从而在权重中占据主导。这 正是 softmax 被称为“软”argmax 的原因——它选出一个赢家， 但仍向其余所有项传递非零信号。

第 7 步

塑造每个 Transformer 的三个旋钮

上面简洁的公式掩盖了三个设计选择，它们决定 该层是有用还是失效。下面将逐一展示，并配以简短的 交互演示。

旋钮 1 — 为何要除以 $\sqrt{d_k}$？

两个随机 $d_k$ 维向量的点积 方差为 $d_k$。随着 $d_k$ 增大，原始得分变得极大，softmax 变得尖锐而趋于 one-hot，梯度随之消失。除以 $\sqrt{d_k}$ 可使方差保持在 1，与宽度无关。

每行中保留下来的权重会经由 softmax 重新归一化， 因此靠前的词元只能看到自身，下一个词元看到自身及其 前一个词元，依此类推。正是这一技巧使 GPT 类模型具备自回归性质。

旋钮 3 — 多头

一张注意力图一次只能表达一种关系。 真实的 Transformer 并行运行 $h$ 个头 — 每个头都有 各自的 $W_Q^{(h)}, W_K^{(h)}, W_V^{(h)}$ — 随后 将其输出拼接。不同的头学会各自专精 （句法、指代、位置邻接、主题）。

每个头看到的输入相同，但使用的旋转不同 （此处我们以四个手动选取的旋转来模拟）。 真实的多头是习得的，但其直观效果一致：它们 关注到不同的事物。

第 8 步

位置：注意力机制暗藏的缺陷

自注意力机制具有 置换不变性。打乱 输入词元的顺序，输出仍是同一组新的向量， 只是重新排列而已。对语言而言这是致命的 — “狗咬人”与“人咬狗”不应相同。

简证。 用置换 $P$ 重排 $X$ 中的 词元。于是 $Q, K, V$ 也随之置换：$Q' = PQ$， $K' = PK$，$V' = PV$。新的注意力输出为 $\mathrm{softmax}(PQ\,(PK)^\top/\sqrt{d_k})\,PV = P\,\mathrm{softmax}(QK^\top/\sqrt{d_k})\,V$。输出 向量的集合完全相同，只是顺序发生了变化。

解决之道 — 引入位置信号

在任何注意力运算开始之前，模型会为每个词元的 嵌入加上一个位置向量 $p_t \in \mathbb{R}^{d_{\text{model}}}$。Vaswani 等人的经典选择是正弦式编码：

每个维度都是波长不同的正弦曲线。 短波长的维度用于区分相近的位置； 长波长的维度则承载相距较远的结构。二者共同 为每个位置赋予唯一的指纹 — 更关键的是， 这一指纹使 相对 位置可以被线性 解码。

有与无 — 重排句子

开启或关闭位置信号，然后打乱词序。 有位置信号时，“river bank”与“bank river”产生的 注意力不同；无位置信号时二者完全相同。

第 9 步

观察一个微型注意力头的学习过程

本文此前出现的每个 Q、K、V 都是为产生 “正确”答案而手工调校的。真实的 Transformer 并不会 凭空获得它们 — 而是通过梯度下降发现它们。现在 让我们在浏览器中进行一次端到端的训练，反向传播全部 手工编码。每个参数、每个梯度、每一步都写于 纯 JavaScript 之中 — 未引入任何外部库。

玩具任务 — 软查找

我们给模型一个含四个词元的序列。前三个 是 候选：每个都携带 $\{A, B, C\}$ 中的 one-hot 标识，外加一个随机的三维负载。第 四个是 query：一个 one-hot，指明我们 想要哪个候选的负载，其负载槽位为零。 模型必须在该 query 位置输出对应的负载 — 一个真正的“按名查找”问题。

第 9 步半

两个头，两位专家

第 7 步说明了多头的存在；第 9 步训练了一个头。现在 观察 两个 头在同一个单头无法解决的 任务上并排训练。每个头拥有各自的 $W_Q, W_K, W_V$（外加一个将两者输出合并的最终线性层）。 损失同时流经二者。

任务：两次相容的查找

该序列有四个词元：两个 A 型对 $(\text{key}_A, \text{val}_A)$ 与两个 B 型对 $(\text{key}_B, \text{val}_B)$。每个词元的输入为 $\bigl[\text{type}\ (2)\;|\;\text{key}\ (3)\;|\;\text{val}\ (3)\bigr]$。 query 词元（第 4 个词元）携带 $\bigl[\text{type-A flag}\ (1)\;|\;\text{key}\ (3)\;|\;\text{type-B flag}\ (1)\;|\;\text{key}\ (3)\bigr]$， 我们要求模型在 query 位置输出 $\text{val}_A + \text{val}_B$。单个头 无法将这两次查找解耦；两个头可以。

第 11 步

注意力机制 并非 的三件事

误解

“注意力不过是加权平均，并无新意。”
权重本身是通过 $QK^\top$ 由数据计算得出 的 — 它们依赖于每一对词元。没有任何 静态的加权和能做到这一点。它是一个 系数在运行时被学得的函数。

误解

“注意力能告诉你模型关注什么。”
注意力权重只是深度模型内部的 一种 信号。 剔除一个低权重的邻词未必会改变 预测结果，而同一个 logit 可以经由多种权重 模式达到。将其解读为解释是有风险的。

误解

“每个词对每个其他词的注意力代价相同。”
自注意力机制在序列长度上为 $O(n^2)$：句子长度加倍， 计算量变为四倍。这正是长上下文模型 采用各种技巧（稀疏、线性、滑动窗口）来削减开销的原因。

第 12 步

我们仍然略去未谈的内容

至此你已看到单头、单层，含位置编码、含掩码、 含多头、含训练的每一个数值。 真实的 Transformer 还有更多：

  • 多层堆叠。 一个 注意力块的输出成为下一块的输入。经过若干 层之后，“bank”所承载的含义由横跨整个句子的 推理链 塑造而成。ViT-Base 堆叠 12 层， GPT-3 堆叠 96 层，据报道 GPT-4 更多。
  • 残差流 + LayerNorm。 每个块都被包裹为 $x \leftarrow x + \mathrm{Attn}(x)$，随后接一个 LayerNorm 和一个 MLP。残差使信息可以原封不动地 跨层传递，如今它被认为正是模型写入其上的 “记忆带”。
  • 交叉注意力。 在编码器-解码器模型 （翻译、T5、图像到文本）中，$Q$ 来自解码器， 而 $K, V$ 来自编码器 — 解码器 “询问源端”而非询问自身。在机制上是同一个 公式。
  • 高效注意力。 $O(N^2)$ 在 长上下文下会急剧膨胀。FlashAttention 重排矩阵乘法以适配 SRAM；滑动窗口（Mistral）、稀疏（Longformer）、 状态空间（Mamba）以及线性注意力（Linformer） 等变体则牺牲少许表达力，换取 $O(N)$ 或 $O(N \log N)$ 的复杂度。
  • 推理时的 KV 缓存。 当聊天机器人 逐个词元地生成文本时，此前所有词元的 key 与 value 都会被缓存并重复使用。在生产部署中，这一缓存 占据了 GPU 显存的大部分。
最后总结。 自注意力机制是 Transformer 用来询问 “我该倾听哪些邻词？”的通用方式。你刚刚手工 计算了这一答案的每一个步骤 — 从产生 Q、K、V 的 投影矩阵，到矩阵形式的 softmax，到位置信息的修正，再到在一个真实的玩具任务上 运行梯度下降。将这一运算在深度与宽度上堆叠起来， 配以残差、MLP 以及十亿级词元的训练集，便是 从原始词元构建出 GPT 级理解力的方式。
