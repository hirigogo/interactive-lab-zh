交互式讲解

再看自动微分

自动微分常常被介绍成一种反向传播的魔法。 其实它比这更简单。它是一种通过对中间值进行存储、并在局部应用链式法则， 从而对实际运行的程序计算精确导数的方法。

在接触交互式计算图之前，我们会先把自动微分与有限差分、符号代数区分开来， 然后直观地勾勒出计算图的运作机制。

约 20 分钟 深度学习 · 优化 · 链式法则
从定义开始 跳转到交互式计算图

一句话概括

\[ \frac{\partial L}{\partial a} = \frac{\partial L}{\partial b} \cdot \frac{\partial b}{\partial a} \]

反向传播将上游梯度从右向左传递。 每个节点贡献一个局部导数。将两者相乘， 把结果发送给父节点，并在路径汇合处进行累加。

不是这样 用微小的 h 反复扰动输入
而是这样 对执行过的中间值进行精确的链式法则记账

I. 自动微分是什么，以及它不是什么

有三种不同的思想常常被混为一谈。它们都在回答 “当输入变化时，输出变化得有多快？”这一问题，但实现方式截然不同。

有限差分

扰动输入并近似斜率

\[ f'(x) \approx \frac{f(x+h)-f(x)}{h} \]

这是一种数值估计。你对输入施加微小改动后重新运行函数。 它可用于梯度检查，但速度慢、结果为近似值，且对 h 的取值敏感。

符号微分

对表达式进行代数改写

\[ \frac{d}{dx}\bigl((x^2+1)^5\bigr) = 10x(x^2+1)^4 \]

它直接操作公式。结果可以是精确的，但大型真实程序并非 整洁的符号表达式。它们包含分支、重复使用的值以及大型复合运算。

自动微分

按局部规则对已执行的程序求导

\[ \text{上游梯度} \times \text{局部导数} \]

这正是深度学习框架所采用的方法。它沿着实际的计算图， 存储前向传播产生的中间值，并产生在常规浮点运算意义下精确的导数。

实践要点。 如果你在训练模型，自动微分才是主力。有限差分主要是一种 调试工具。符号微分则属于另一类系统。

II. 进入交互视图前的计算图速写

这里用静态形式呈现整个思想。前向传播从左到右 生成中间值。反向传播把梯度从损失传回叶节点。 计算图之所以重要，是因为它精确地告诉我们谁依赖于谁。

一个节点只需少量内存

node = {
  value,
  parents,
  backward(upstream) {
    return parents.map((parent) => upstream * localDerivative(parent));
  }
}（节点对象：保存值、父节点与反向规则）

III. 每个引擎都需要的微型规则手册

标量版本的自动微分凭借一张很小的查找表就能走得很远。下面这份确切清单 与动画讲解中的教学核心一致：乘法、加法、指数、倒数与对数。 更复杂的运算都由这些基本运算搭建而成，或被封装进一个内部懂得如何反向传播的更大模块中。

IV. 一个例子：前向与反向全程追踪

现在我们可以对一个具体的标量计算图进行动画演示。从一个正类样本开始。 我们将由标量 logit z = wx + b 计算对数损失。该表达式被 刻意展开为一个个微小运算，以便你能看清引擎在底层究竟做了什么。

\[ L = -\log\!\bigl(\sigma(wx + b)\bigr) = -\log\!\left(\frac{1}{1 + e^{-(wx+b)}}\right) \]

V. 框架为何把计算图折叠为模块

用于教学的计算图应展示一切。用于生产的计算图则只展示恰到好处的部分。 这就是框架把一串微小运算打包成更大模块的原因。线性层隐藏了乘法与加法。 sigmoid 隐藏了取负、指数、加法与倒数。损失模块则能隐藏更多。

VI. 三个样本、共享参数、一次更新

自动微分的意义不在于单个样本，而在于反复复用。相同的参数 会出现在每个样本中，因此反向传播必须在优化器更新参数之前 累加梯度贡献。仅用三个数据点，你就能亲身感受到批量处理逻辑， 而不只是把它当作抽象概念。

\[ J(w,b) = \frac{1}{N} \sum_{i=1}^{N} \left[-y_i\log p_i - (1-y_i)\log(1-p_i)\right], \qquad p_i = \sigma(wx_i + b) \]

VII. 自动微分引擎真正存储了什么

完整的故事比那些记号看起来要小。一个节点存储一个值、 一组父节点以及一条局部反向规则。前向传播构建计算图，并缓存 反向规则之后所需的一切。反向传播从标量损失出发， 按逆拓扑序遍历计算图，并在多条路径汇合处累加贡献。

1. 局部优于全局

每个节点只需知道它自己那条微小的求导法则。

引擎从不符号化地对整个模型求导。它组合许多局部事实。

2. 缓存很重要

前向值之所以被保存，是因为反向规则需要它们。

对于 \log(a) 你需要 a；对于 1/a 你需要 a；对于 sigmoid，通常需要其输出。

3. 模块化并非作弊

它们只不过是内部反向规则更丰富的更大节点。

这正是 nn.Linear、sigmoid 与交叉熵得以既易用又保持可微的方式。

4. 批量只是增加了累加

在更新之前，相同的参数会收到多条梯度信息。

优化器步骤之所以简单，只是因为自动微分已经把所有依赖于这些参数的量都求和了。

如果这一节让你理解了，那么下一个不错的练习就是自己动手实现标量引擎。 让计算图保持小巧，让规则手册保持简短，让反向传播保持诚实。
