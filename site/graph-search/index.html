图搜索：逐层推进前沿

BFS（广度优先搜索） 能在无权图上找到最短路径，却因盲目探索而浪费精力。Dijkstra（迪杰斯特拉） 能处理边权，却无视目标所在。A* 引入启发式函数便能径直抵达——前提是该启发式是可采纳的。在网格上绘制墙壁，观察四种搜索算法如何扩展各自的前沿，并看清每一种究竟在何处浪费了工作。

约 16 分钟 数据结构 · 图搜索 · A*
前言

同一套脚手架，四种算法

四种经典的单源最短路径 / 可达性算法——BFS（广度优先搜索）、DFS（深度优先搜索）、Dijkstra（迪杰斯特拉）、A*——共用同一套脚手架。维护一个前沿，其中存放已发现但尚未最终确定的节点。取出一个，标记为已确定，将其邻居加入前沿。重复此过程，直至抵达目标（或前沿清空）。

它们之间的差异何在？在于支撑前沿的数据结构。

  • BFS（广度优先搜索）使用 FIFO 队列 → 先取出最浅的节点 → 在无权图上找到最短路径。
  • DFS（深度优先搜索）使用 LIFO 栈 → 先取出最深的节点 → 找到某条路径而非最短路径，但内存占用少得多。
  • Dijkstra（迪杰斯特拉）使用以当前路径代价为键的最小优先队列 → 取出离起点代价最低的节点 → 在边权非负的带权图上达到最优。
  • A*使用以 $f(n) = g(n) + h(n)$ 为键的最小优先队列（当前代价加上到目标的启发式估计）→ 取出最有希望的节点 → 只要 $h$ 可采纳即为最优。

优先级顺序不同，行为便不同，底层循环却相同。

值得尝试的操作：

  • 清除墙壁，在同一空网格上运行 BFS（广度优先搜索） 与 A*。BFS（广度优先搜索） 会探索一个近似方形、半径等于到目标距离的区域。A* 则绘出一个指向目标的椭圆。最短路径相同，工作量却天差地别。
  • 在起点与目标之间绘制一条长长的水平泥地带。运行 BFS（广度优先搜索）——它对每一步一视同仁，因此径直穿过。运行 Dijkstra（迪杰斯特拉）——它会绕行。
  • 在目标周围绘制一道 C 形墙壁，使算法不得不回溯。运行贪心最佳优先；它会一头扎向目标，直到被挡住才意识到错误。A* 能够恢复；贪心则不能。
  • 在空网格中运行 DFS（深度优先搜索）。它会产生一条极其漫长的路径，随后走到尽头便放弃。DFS（深度优先搜索） 不适用于最短路径问题，而这一演示使其显而易见。
第 2 步

BFS（广度优先搜索）——无权图的最短路径工具

从 FIFO 队列中取出。每次取出要么是目标（返回），要么将其未访问的邻居入队。由于队列是 FIFO 的，每个节点都在其最浅的发现深度被取出——即距起点的边数。

BFS（广度优先搜索） 在无权图（或边权一致的图）上是最优的，运行时间为 $O(V + E)$。一旦各边权重不同，它就不再最优：BFS（广度优先搜索） 将泥地单元格与空地单元格同等对待。这正是 Dijkstra（迪杰斯特拉） 所解决的问题。

第 3 步

DFS（深度优先搜索）——深度优先，因别的理由而有用

从 LIFO 栈而非队列中取出。你会尽可能深入，直至需要回溯。DFS（深度优先搜索） 对于最短路径是错误的算法——但下列场景中它却是正确的选择：

  • 拓扑排序。对 DAG 做后序 DFS（深度优先搜索） 可得到逆拓扑序。
  • 环检测。DFS（深度优先搜索） 期间出现回边即意味着存在环。
  • 连通分量。每次顶层 DFS（深度优先搜索） 调用勾勒出一个分量。
  • 内存。DFS（深度优先搜索） 使用 $O(\text{depth})$ 内存；BFS（广度优先搜索） 使用 $O(\text{前沿 width})$。在宽而浅的图上，DFS（深度优先搜索） 占优。
  • 割点 / 桥。Tarjan 算法通过单次 DFS（深度优先搜索） 遍历同时提取二者。

上方的网格演示做的是最短路径，这对 DFS（深度优先搜索） 而言是错误的差事——不妨一试，观察它找到的那条荒谬路径。

第 4 步

Dijkstra（迪杰斯特拉）——带优先队列的 BFS（广度优先搜索）

将 BFS（广度优先搜索） 的 FIFO 队列替换为以当前已知的最优起点代价为键的最小优先队列。取出代价最小的节点。第一次取出某节点时，你就得到了它的最终最短路径代价。通过松弛更新邻居：

使用二叉堆时（参见树一文），Dijkstra（迪杰斯特拉） 运行时间为 $O((V + E) \log V)$。使用斐波那契堆时为 $O(V \log V + E)$，因为 decrease-key 操作摊还后变为 $O(1)$。

仅限非负边。其正确性证明依赖于每条边都具有非负权重。若存在负权边，Dijkstra（迪杰斯特拉） 便不再安全；应改用 Bellman-Ford（贝尔曼-福特）（$O(VE)$）。若图为 DAG，还能做得更好：按拓扑序松弛，达到 $O(V + E)$。
第 5 步

A*——带提示的 Dijkstra（迪杰斯特拉）

Dijkstra（迪杰斯特拉） 对目标身处何方毫无概念。A* 修正了这一点：将优先级的键从「自起点起的代价」改为「经由此节点的估计总代价」：

其中 $g(n)$ 为自起点到 $n$ 的实际代价，$h(n)$ 为从 $n$ 到目标的剩余代价的启发式估计。有三种情形：

  • $h \equiv 0$。A* 恰好退化为 Dijkstra（迪杰斯特拉）。慢，但最优。
  • $h$ 恰好等于真实的剩余代价。A* 只扩展最短路径上的节点。最优，且达到可能的最快速度。
  • $h$ 介于两者之间。A* 大致扩展那些 $f$ 值不超过最优值的节点带。$h$ 越紧，带宽越窄。

为保证正确性，我们需要 $h$ 是可采纳的——它绝不能高估真实的剩余代价。在步长一致的四连通网格上，曼哈顿距离是可采纳的。在八连通（含对角）网格上，应使用切比雪夫距离或 octile 距离。欧氏距离在任何地方都可采纳，但在网格图上较为宽松。

为使 A* 从不重新扩展节点，我们还要求 $h$ 是一致的（又称单调）：对每条边 $(n, n')$ 都有 $h(n) \le c(n, n') + h(n')$。网格上大多数「显然」的启发式——曼哈顿、欧氏——都是一致的。

第 6 步

贪心最佳优先——前车之鉴

若仅按 $h(n)$ 排序优先级，而无视已付出的代价，会怎样？那就是贪心最佳优先搜索。它感觉像是丢掉了 $g$ 项的 A*，在简单地图上能极快地找到一条路径。但一旦贪心方向与目标之间横着一道墙，它便会一头扎进死胡同，再艰难地挣扎出来。

贪心最佳优先并不最优。它会产生某条路径，可能远非最短。适用于以下情形：(a) 你信任该启发式；(b) 你更看重速度而非最优性；(c) 路径不佳时你可以重新规划。除此之外：请用 A*。

第 8 步

易错之处

  • BFS（广度优先搜索） 是迭代加深的朋友，而非其替代。若你的图是无限的（或实际上无限），BFS（广度优先搜索） 将在完成之前就把前沿的内存耗尽。迭代加深 DFS（深度优先搜索）（IDDFS（深度优先搜索））保留了 DFS（深度优先搜索） 的 $O(\text{depth})$ 内存，同时仍能找到最短路径。
  • A* 的重新扩展。若启发式可采纳但不一致，某节点可能以更优的 $g$ 被重新加入前沿。处理方法是检查弹出节点的 $g$ 是否与记录的最优值相符；若不符则跳过。
  • A* 中的平局打破很重要。两个 $f$ 相等的节点可能以不同顺序被弹出，而该顺序会改变 A* 返回的路径。标准技巧：打破平局时优先选择较大的 $g$（更接近目标）。这往往能大幅缩小已探索集合。
  • 双向搜索。同时从起点与目标运行 BFS（广度优先搜索） / A*；当前沿相遇时停止。最好情况下将工作量开平方（分支因子为 $b$、深度为 $d$ 时，由 $O(b^d)$ 变为 $O(b^{d/2})$）。
  • 跳点搜索。在单位代价网格上，当没有值得关注的变化时，可以整段跳过单元格。在游戏地图上比 A* 提速一个数量级。
  • D* 与 LPA*。当图发生变化（障碍出现、边被关闭）时，从零重新规划颇为浪费。D* Lite 复用上一次运行的信息；它是火星车路径规划器背后的经典算法。
