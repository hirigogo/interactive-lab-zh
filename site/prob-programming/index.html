第 1 步

概率编程语言（PPL）是什么 —— 以及不是什么

概率编程语言让你以代码的形式编写生成模型。你声明先验、采样分布、观测；运行时负责后验推断。同一个模型只需改动一行开关，就可以用 HMC、NUTS、ADVI、SMC 或拉普拉斯近似来运行。

工具后端优势特点
Stan自研 + C++最好的 NUTS 采样器；对分层模型极为稳健使用不同的语言；编译较慢
PyMCPyTensor / JAXPython 风格；用户基础庞大；工具丰富（ArviZ）首次运行时有编译时间
NumPyroJAX通过 JAX 实现快速 NUTS；对 GPU 友好；与深度学习的互操作最为干净社区比 PyMC 小
Turing.jlJulia可与 Julia 的机器学习技术栈组合；灵活仅限 Julia
PyroPyTorch可对大型模型做随机 VI；适合 BNN / 隐变量模型HMC 不如 NumPyro 成熟
Edward2 / TFPTensorFlow可扩展；有生态系统的接口API 变动频繁
一句口号。 你只需写一次数学。PPL 负责推断。在 HMC 与 VI 之间切换只是改一个标志，而非重写代码。
第 2 步

伪代码模板

with model:
    theta = Beta("theta", alpha=1, beta=1)        # prior
    y = Binomial("y", n=20, p=theta, observed=14) # likelihood + obs

    trace = sample(2000, chains=4)                 # NUTS
    az.plot_trace(trace)
    az.summary(trace)                              # r-hat, ESS

每个 PPL 都为你提供三样东西：

  1. 声明式模型。 变量有名称，分布有先验，观测与数据相绑定。
  2. 推断引擎。 默认使用 NUTS / HMC；按需使用 VI / 拉普拉斯近似。
  3. 诊断信息。 r-hat（链间收敛性）、ESS（有效样本量）、发散转移、后验预测检验。

第 4 步

实时：二维贝叶斯回归 —— HMC 与 VI 对比

一个小数据集上的贝叶斯线性回归。HMC 给出诚实的后验；均值场 VI 拟合一个因子化的高斯分布。观察可信带如何不同：VI 通常过窄，尤其是在参数存在相关性的方向上。

n —
(斜率, 截距) 上的 HMC 后验
VI 高斯拟合（均值场）
VI 的陷阱。 均值场 VI 在参数之间做因子化分解，因此无法表示相关的后验。HMC 的等高线常常是倾斜的；而 VI 的等高线总是与坐标轴平行。若要获得高质量的可信区间，宜选用 HMC 或满秩 VI。
第 5 步

诊断清单

  • r-hat < 1.01。 每个参数上的链间一致性。高于 1.05 = 链尚未收敛；请运行更久或重新参数化。
  • ESS > 400。 有效样本量。低于此值，你的后验摘要会有噪声。
  • 发散转移。 NUTS 特有的问题。哪怕只有 5 次发散（占链的 ≥ 0%）也意味着几何过于弯曲 —— 试试非中心化参数化，或增大 target_accept。
  • 后验预测检验。 从后验模拟新数据，并与观测数据比较。此处拟合不佳，其重要性远胜过任何单一诊断。
  • 先验预测检验。 仅从先验采样。若这些样本看起来不合理，则你的先验是以一种糟糕的方式无信息的。
  • LOO / WAIC。 用于模型比较的交叉验证预测精度。ArviZ 两者都提供。
第 6 步

PPL 适合（以及不适合）做什么

  • 合适的场景。 分层模型、少数据、校准良好的不确定性、参数解释、带机制性先验的科学模型。
  • 改用其他方案： 数百万样本上的深度学习（梯度下降更快）、纯点估计（sklearn / XGBoost）、生产环境部署（PPL 在研究里很棒，在生产里则很别扭）。
  • 深度 BNN 的鸿沟。 贝叶斯神经网络很难。PyMC + NUTS 在参数超过几千个后就难以为继；对贝叶斯深度模型做 VI 是有偏的。SWAG、拉普拉斯近似、深度集成与 SGLD 是实用的折中方案。
